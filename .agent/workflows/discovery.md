# /discovery — Product Discovery

Run this workflow when starting a **new product idea** or when the user wants to explore and refine what they're building.

## Prerequisites
- The user has an idea (even a rough one) they want to explore

## Steps

### 1. Understand the Idea
Ask the user to describe their product idea in plain language. Guide them with these questions:

- **What does it do?** What's the core action or thing this product enables?
- **Who is it for?** Who will actually use this? Be specific (not "everyone").
- **What problem does it solve?** What's painful or annoying without this product?
- **How serious are you?** Just exploring / personal use / share with others / public launch

> If the user has already answered some of these, acknowledge what you know and fill in the gaps.

### 2. Challenge Assumptions
Review what the user said and push back constructively:

- Is the scope realistic for a v1?
- Are they solving a real problem or building a solution looking for a problem?
- Are there existing tools that do this? What would make theirs different?
- Is the target audience too broad?

> Be honest but supportive. The goal is clarity, not discouragement.

### 3. Separate Must-Haves from Nice-to-Haves
Work with the user to categorize features:

| Priority | Features |
|----------|----------|
| **Must Have (v1)** | Core features that define the product — without these, it doesn't work |
| **Should Have (v1.1)** | Important but not launch-blocking — add right after the core works |
| **Nice to Have (v2+)** | Cool ideas to revisit later — don't let these slow down v1 |

### 4. Suggest a Smart Starting Point
If the idea is too big, propose a **Minimum Lovable Product (MLP)** — the smallest version that:
- Solves the core problem
- Looks and feels professional (not a bare MVP)
- Can be built and shipped quickly

### 5. Produce Discovery Summary
Create a concise summary document covering:
- Product name (or working title)
- One-line description
- Target user
- Core problem
- v1 feature list (must-haves only)
- Deferred features
- Open questions or decisions needed
- Recommended next step

> Save this as an artifact so it carries forward to Planning.

## When to Move On
Move to `/planning` when:
- [x] The user agrees on what v1 should include
- [x] Must-haves are clearly defined
- [x] No open questions are blocking progress
